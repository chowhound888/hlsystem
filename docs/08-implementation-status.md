# 当前实现与验收范围

更新日期：2026-10-09。本文件描述可运行版本，前七份设计文档描述完整目标。不能仅凭菜单或表定义判断目标已完成。

当前数据库已执行扩展教学数据：30 个药品规格、33 个患者、43 个就诊、60 张门诊处方、16 条住院医嘱、323 个库存余额、78 个批次、6 条规则、7 条知识、12 个生产订单和 231 张凭证。库存流水与凭证平衡检查通过；重复运行扩展脚本不会重复增加数据。

## 已实现的核心流程

| 模块 | 当前可操作内容 |
| --- | --- |
| 系统基础 | 会话登录、CSRF、七角色、机构范围、用户新增停用、重置密码、组织机构、审计、基础字典 |
| 药品与物料 | 药品分页搜索、别名、规格、厂家、单位换算、医保和特殊标志、停用；原辅料与包装物料新增 |
| 药库 | 采购建议与计划审核、入库草稿及双人审批、赠药和实验药来源、批次成本层、调拨在途及分次接收、领药申请转调拨、报损、退供、流水、盘点冻结与差异、日月年结与重开 |
| 门诊 | 患者和就诊录入、处方、用药审查、划价及库存预留、缴费、独立复核与发药、控制药登记、部分退药及退款 |
| 住院 | 住院登记、押金、临时长期及隔日医嘱、按日生成执行实例、确认记账、摆药复核、另一人发药、整次退药冲回、病区基数与消耗 |
| 会计与价格 | 自动平衡凭证、应付付款、发药收费对账、库存与流水成本核对、手动调价与已批准自动调价、价格历史、估值明细 |
| 制剂 | 配方快照、生产计划独立审核、原料入库待检、原料检测及独立放行、批次领料、工序记录、成品质检、人工能源材料成本、成品放行入库和销售收款出库 |
| 合理用药 | 过敏、相互作用、剂量、禁忌、适应症、重复药品/成分；缺资料状态、普通理由放行、严重阻断、规则维护、药品知识 |
| 输出 | 日期范围出入存报表、柱形图、Excel、独立单据/处方打印页、签字栏、打印模板字段与方向 |

增补：长期医嘱每日定时生成；半成品可以作为配方产出再投入后续订单；生产退料按原批次成本回库，异常损失单独过账；手工凭证保存草稿并由不同人员过账；入库/领用/报损整单冲销，在途退回和报损；全院销售净额、综合加成率、月度收支、科室门诊消耗与制剂成本分析。

## 验证方式

`front/tests/api-smoke.mjs`：核心跨角色链路，真实 MySQL 写入与核算。

`front/tests/api-controls.mjs`：库存预留与释放、分次调拨、盘点冻结、过敏阻断、失败回滚、结账重开与报表导出。

`front/tests/ui-smoke.mjs`：实际页面、桌面及窄屏截图、运行错误与整页溢出检查。

`front/tests/api-concurrency.mjs`：竞争出库防超卖及并发重复押金请求。

`front/tests/api-corrections.mjs`：整单冲销、在途报损后接收、手动及自动调价、成本流水和借贷平衡。

已执行的 API 验收会保留在演示库中，测试并不重置数据库。反复执行会新增处方、生产订单等记录。

## 完整设计中的后续细项

当前完成核心可演示版本，以下细项尚未达到设计文档的完整深度，不能声称六大模块每一条原始要求全部验收完成：

- 多供货商报价、按最近消耗及供货周期的完整采购预测、分批采购收货和逐行实际价格。
- 住院跨医嘱组合审查与完整分类统领打印；原医嘱与药品分类已保存在实例关联中。
- 病区患者用药收费分摊；现有基数药消耗按机构和用途记成本。
- 外部财务交换与全部科室统计口径；当前科室汇总主要覆盖门诊，库存成本及发药收入在全院账务中统计。
- 制剂返工、同一订单分批产出与配方版本批准；当前单订单结算一次，半成品链通过多个订单完成。
- 规则与知识的独立批准、完整版本管理、跨处方重叠检查与更广的成分分类模型。
- Excel 导入、附件、单据字段列宽设置、首登强制改密，以及全部 A01—A25 场景的自动化覆盖。
