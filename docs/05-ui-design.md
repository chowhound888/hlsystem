# 前端 UI 与交互设计

## 1. 设计方向

面向药库人员、药师和会计的中文业务后台。采用 Element Plus，页面围绕待办、查找、核对和执行展开。信息层级是页面标题 → 筛选 → 操作 → 数据 → 汇总；日常工作页面优先展示表格和任务队列。

参考 `ui-ux-pro-max` 的 Data-Dense Dashboard 建议，采用适量绿色与蓝色业务强调、清晰表格、状态反馈和 Pinia。搜索工具同时给出的宣传首页结构与本项目用途不符，页面结构按业务工作台设计。

系统名称暂用“药品管理分系统”，医院名称由配置带出。登录后直接进入角色工作台；支持机构切换与最近访问页，不添加宣传首页。前端只实现浅色主题，暗色主题不是第一版验收项。

## 2. 视觉规范

| 项目 | 规范 |
| --- | --- |
| 主操作色 | 蓝色 `#2563EB`，提交、保存、主要操作 |
| 医药业务强调 | 绿色 `#15803D`，已完成与合格状态 |
| 页面背景 | `#F5F6F8`；工作区域白色 `#FFFFFF` |
| 正文 | `#20242B`，辅助文字 `#59616D` |
| 边框 | `#DDE1E6`，表格线和区域分隔 |
| 警告与危险 | `#B45309`、`#B91C1C`，配合文字和图标 |
| 字体 | 系统中文字体：Microsoft YaHei / PingFang SC / sans-serif，不依赖在线字体 |
| 字号 | 正文 14px、辅助 12px、页标题 20px、区域标题 16px；不随视口宽度缩放 |
| 间距 | 4/8/12/16/24px，内容区通常 20px |
| 圆角 | 输入与按钮 4px，独立弹窗 6px，不把页面区块包装成浮动卡片 |
| 图标 | Lucide Vue，通常 16—20px；图标按钮具有名称 tooltip 和 aria-label |
| 行高 | 表格默认 40px，可切换紧凑 34px；工具栏与按钮尺寸稳定 |
| 金额与数量 | 右对齐、等宽数字、金额到分；标题注明基础单位和核算口径 |
| 状态 | 中文标签 + 图标，不能仅靠颜色表达 |

工作区域以浅中性背景为主，蓝色用于操作，绿色用于合格，橙红用于异常；不用绿色覆盖全部页面。表格首列及操作列可固定，患者姓名和药品名有足够空间，长内容允许换行或显示完整详情。

## 5. 核心页面

### 5.1 角色工作台

顶部用一条指标带展示待审核、待接收、低库存、近效期。主体左侧为带期限与机构的待办列表，右侧为预警列表。底部用趋势折线和分类条形图展示近七日消耗；不堆积装饰性图表。

药师默认进入待发药队列，会计默认进入对账与待报账；可通过工作台页签切换汇总。图表可点击进入带过滤条件的明细列表。

### 5.2 库存与流水

筛选：机构、药品关键字、药品类别、控制等级、效期范围、库存状态。表格列：药品编码/名称/规格、批号、有效期、质量、在手/预留/可用数量、单位、采购成本、零售估值。列选择支持保存用户偏好。

展开药品行查看批次，批次详情查看成本层、来源单据、调拨在途和流水。基础单位与包装数量同时展示，例如 `234 片（9 盒 18 片）`，金额口径不能靠 tooltip 才知道。

库存流水采用日期与单据列表，列出变动数量、变动成本、结存、操作者。点击来源跳转单据；导出与查询范围一致。

### 5.3 单据编辑与详情

整页编辑大单据，上方机构、日期、供应商、原因等基本资料，中部可编辑明细表，下方合计与附件，底部固定操作栏。小型资料编辑使用抽屉；复杂单据不塞进狭小弹窗。

药品选择器支持编码、通用名、商品名、别名、拼音；输入模糊别名时展示规格和厂家供人工确认。选择后带出单位与换算，库存相关字段由服务端计算。新增明细时保持焦点，支持键盘选择。

详情页展示中文状态、源单据、明细、审批时间线、执行流水、打印预览与退款/冲销关联。只有适用动作显示在操作栏；执行确认框明确机构、数量、金额和不可直接修改的后果。

### 5.4 门诊复核发药

```text
┌────────────────────────────────────────────────────────────────────┐
│ 状态页签：待审核 | 待缴费 | 待复核 | 待发药 | 已发药 | 退药        │
├───────────────────┬────────────────────────────────────────────────┤
│ 患者/处方搜索     │ 患者、就诊、医生、收费状态、处方号             │
│ 队列：姓名、科室  │ 过敏 / 严重风险 / 普通警告                     │
│ 处方号、等待时间  │ 药品、剂量、发药数量、单位、批次、效期、金额   │
│                   │ 审查详情 / 批次分配 / 审核轨迹                  │
│                   │ 合计与缴费金额                                 │
├───────────────────┴────────────────────────────────────────────────┤
│ 当前复核人 / 发药人                    驳回 | 复核通过 | 确认发药 │
└────────────────────────────────────────────────────────────────────┘
```

风险提示放在患者与药品明细之间，不被折叠隐藏。已缴费、审查、复核、库存、人员条件未满足时，按钮旁展示具体阻断原因。操作后刷新队列并保持相邻任务，避免整个页面跳回首页。

### 5.5 住院医嘱与摆药

以病区、执行日期、时段、医嘱类型筛选。表格显示患者、床位、药品、频次、执行时间、费用、押金余额、审查与执行状态。选择符合条件的实例生成摆药单，不能把多个不同机构混为一张单。

摆药页提供患者明细与药品统领两个页签，药品分类用分组切换。欠费、停嘱、资料缺失、预留失效显示在对应行，批量动作返回逐项失败原因。中草药处方打印保留药味、剂量、煎服说明。

### 5.6 会计对账与调价

对账页上方选择时间、机构和口径，下方分“匹配成功、时间差、待报账、真实差异”页签。每行能打开收费、发药、退药和凭证，处理差异须说明原因。

调价页左右展示旧价与新价，标明生效时间、确认模式和批准依据。确认前展示预计影响数量和零售估值；执行后展示实际快照。使用表格和明细钻取解释金额变化。

### 5.7 制剂生产

生产详情页顶部显示订单、配方版本、产量与状态；主体页签为物料批次、工序、质检、产出、成本和操作轨迹。质检结果显示标准、实测和判定，未合格或未定成本产出有明确冻结标志。

成本页按材料、人工、能源、其他、异常损失展示，再显示合格产量和单位成本。图表可比较标准与实际，但结算依据仍是明细表。

### 5.8 合理用药

规则页按类型、严重度、药品与版本过滤，条件采用结构化表单。审查详情显示命中药品、患者条件、规则版本、原因、建议及放行记录。知识页支持检索、批准状态与来源；示例资料在详情中标明“课程演示”。

## 6. 共用交互与状态

- 列表保留筛选条件，查询重置到第一页；汇总使用完整过滤范围，不仅统计当前页。
- 加载时固定布局；空列表提示无记录，查询无结果可清空筛选；请求失败支持重试。
- 表单字段旁显示具体校验原因，金额、数量、日期边界由前后端共同校验。
- 多行单据离开页面提醒未保存；提交执行时禁用重复按钮，重试复用幂等键。
- 并发修改返回版本冲突，提示刷新详情；不能覆盖其他人的审核结果。
- 风险、质检失败、欠费提示包含下一步操作，不能只显示“操作失败”。
- 数量与金额输入有单位及精度，客户端不得用 JavaScript 浮点计算确认金额。
- 标准工具用图标及 tooltip；保存、提交、审核、发药等明确命令使用图标加文字。
- 页面键盘焦点可见，标签与输入关联；标签不能只用占位文字。

## 7. 适配与打印

主要验收视口为 1440×900 与 1920×1080，同时检查 1280×720。1024 宽度折叠侧栏，筛选换行；768 以下采用抽屉导航和单列表单，复杂表格只在表格容器内滚动，整页不得出现横向溢出。手机优先查看、待办与简单审核，不承诺与桌面相同的密集摆药效率。

打印默认 A4，出入库可选择横向，处方和摆药可选择纵向。隐藏导航与按钮，重复表头，页面显示单据号、机构、业务日期、页码、制单/审核/执行人和手写签字栏。长表跨页不能截断合计或签字。

模板配置仅调整许可字段、排序、宽度、标题、纸型与签字位置，数量金额合计和来源标识不可隐藏。每次打印使用已执行交易快照；浏览器打印预览与 Excel 使用同一后端数据过滤口径。

## 8. 后续 UI 验收

实施时用 Playwright 截图检查工作台、库存、单据、发药、医嘱、对账、制剂页以及打印预览。验证文字换行、固定列、弹窗、禁用态、错误态及各视口，避免遮挡和布局跳动。本阶段没有制作网页原型或截图，以上线框图为页面布局设计。
