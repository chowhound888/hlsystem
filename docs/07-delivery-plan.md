# 开发阶段、演示数据与验收

## 1. 实施顺序

不设虚构工期。每阶段验收通过后进入下一阶段，六大模块全部在最终交付范围内。开发开始前确认本机工具版本和 MySQL 连接参数；规划完成不等于授权执行数据库变更或开始实现。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 0：设计基线 | 当前七份专题文档及索引 | 需求、核心业务与数据口径一致 |
| 1：工程与基础 | 前后端工程、迁移、登录、七角色、机构范围、布局、基础字典 | 不同角色登录；可维护药品单位和组织；越权被阻止 |
| 2：库存与药库 | 批次成本层、库存流水、采购建议、入库、调拨、领药、盘点、报损、退供、预警 | 一次采购从计划到入库调拨完成；数量和成本平衡 |
| 3：临床与门诊 | 患者、就诊、处方、划价、缴费、初版用药检查、双人复核发药、退药退款 | 完成门诊整条链路，过期、缺货、同人复核被阻止 |
| 4：住院 | 入院、押金、临时长期医嘱、执行调度、摆药、统领、基数药、退药 | 隔日医嘱不重复生成；欠费处理留痕；摆药和发药不重复扣费 |
| 5：会计与价格 | 从阶段 2 接入的基础凭证扩展为会计 UI、调价、对账、应付付款、日月年结与统计 | 源事件唯一过账，借贷与库存一致，关账阻断回写 |
| 6：制剂 | 物料、配方版本、原料质检、领料、工序、半成品成品、成本、销售付款、报表 | 原料批次到成品可追溯，未检/未定成本不可发出 |
| 7：合理用药完善 | 六种审查、可维护规则、知识、版本、资料不足状态和警告放行 | 六类样例分别触发，严重阻断，普通理由放行，历史可追溯 |
| 8：完整交付 | 全模块打印模板、Excel、界面检查、集成验收、演示脚本、运行说明 | 六大模块连续演示通过，核心异常自动检查通过 |

会计基础表及过账服务在库存阶段就建立，费用流水在临床阶段建立，不等到阶段 5 才补历史账。合理用药审查接口在门诊阶段就接入，最终阶段完善规则维护及更多类型。

每阶段包含实际页面、后端业务、SQL 迁移与针对性验证，不先生成所有菜单再逐个用静态数据填充。

## 2. 演示数据方案

| 类别 | 计划数据 |
| --- | --- |
| 组织 | 1 家虚构医院、2 个药库、2 个门诊药房、2 个住院药房、1 个制剂库、若干科室与病区 |
| 账号 | 七类角色；至少 2 位门诊药师、2 位药库业务账号、2 位制剂岗位账号；凭证审核另用会计账号 |
| 药品 | 约 30 个规格，覆盖普通、抗菌、针剂、输液、中药、毒麻精神、贵重、进口、自费、院内制剂 |
| 批次 | 每个常用药 2—3 个批次，含同批不同购价、近效期、过期、隔离和低库存情况 |
| 物料 | 原辅料与包装约 10 种，2 种制剂产品及相关半成品 |
| 临床 | 虚构患者约 20 人，门诊与住院就诊，含体重缺失、过敏、欠费和长期隔日医嘱 |
| 规则 | 每种审查至少 2 个示例，覆盖通过、警告、阻断、无法判定 |
| 交易 | 至少覆盖一个月末结账；提供独立可重置场景测试年结，不要求人工逐日造一年数据 |

默认演示密码由初始化输出或本地配置提供，首次登录提示修改；不用真实患者和临床规则。导入演示数据不会操作用户其他数据库。

## 3. 核心验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 10 盒、每盒 24 片入库，发 6 片 | 剩余 234 片；来源成本与数量可追溯 |
| A02 | 同批号两次不同购价入库 | 两个成本层，出库按实际层分摊，不覆盖旧成本 |
| A03 | 并发发药争抢最后一批库存 | 只允许满足数量的事务成功，无负库存 |
| A04 | 同一个执行请求点击两次或超时重试 | 一次库存变化、一次账务事件、相同结果 |
| A05 | 药库发 100，药房接收 60，再接收 40 | 中间在途 40，最终在途 0；全院数量与成本不变 |
| A06 | 调拨短少 5 | 剩余在途保留，经审核退回或报损才闭环 |
| A07 | 盘点期间尝试发出冻结物料 | 被阻断；盘点差异审核后入账，解除锁 |
| A08 | 过期批次、待检原料尝试出库 | 被阻断；正常批次按近效期分配 |
| A09 | 处方有警告或严重相互作用 | 普通逐项理由放行；严重必须修订；不可显示为普通通过 |
| A10 | 处方剂量需体重但患者缺体重 | 显示无法判定，要求补资料或按规则处理 |
| A11 | 未缴费发药；同一药师复核发药 | 均被阻止，界面说明具体条件 |
| A12 | 处方发药后部分退药再退款 | 仅回原批次成本，累计退量及退款不超原额 |
| A13 | 退款与发药同时执行 | 源单锁保证只出现合法结果，无退款后发药 |
| A14 | 调价前划价、调价后发药 | 使用旧交易快照；新处方用新价；库存采购成本不变 |
| A15 | 住院确认执行后再次生成摆药 | 无重复收费；摆药只是编组，发药只扣一次库存 |
| A16 | 长期隔日医嘱调度重跑并停嘱 | 无重复实例，未来实例取消；已发出保留并走退药 |
| A17 | 住院欠费 | 默认阻断；授权理由放行保存操作者与负余额 |
| A18 | 药房补病区基数药后病区使用 | 补充是调拨，实际使用才计消耗；不重复核算 |
| A19 | 制剂未质检或未成本结算尝试销售 | 被阻断；合格产品成本与投入、异常损失平衡 |
| A20 | 原料领出部分退回、配方后来升级 | 成本正确冲回，生产仍用原批准配方版本 |
| A21 | 两次供应商付款或超额退款 | 余额锁和唯一事件保证不超付、不超退 |
| A22 | 已月结日期执行新单据 | 被阻止；当前期冲销关联原单，历史快照不被修改 |
| A23 | 药师修改 locationId 访问其他药房 | 后端拒绝，打印导出也不泄露 |
| A24 | 日月年汇总、流水、凭证核对 | 数量、成本、金额口径一致，时间差单独列出 |
| A25 | 单据多页打印与导出 | 表头重复、合计与签字完整，导出过滤和权限一致 |

## 4. 测试分配

- 单位换算、FEFO 分配、剂量换算、综合加成率和制剂成本分摊用单元测试验证边界与舍入。
- 库存、付款、退款、调拨、调价切点、关账及任务重跑使用 MySQL 集成测试，重点验证锁与事务回滚。
- 对登录、跨角色门诊、住院、制剂流程使用少量 Playwright 端到端用例；测试数据可隔离重置。
- 对复杂前端表单和状态控件采用 Vitest；格式与类型检查覆盖整个前端。
- 页面截图验证桌面、窄屏、错误态、长药品名、打印跨页。截图验收在实现后进行。

每个阶段执行适用检查，验证已足够时进入下一阶段。SQL 迁移在空数据库及上一版本数据库各验证一次，不能只验证开发机最终状态。

## 5. 答辩演示路线

1. 医院组织、七类角色和药品字典；用药品别名定位同一规范药。
2. 自动采购建议 → 审核采购 → 批次入库 → 药房申请 → 药库发货 → 药房接收。
3. 患者就诊 → 医生处方 → 用药警告 → 药师说明处理 → 缴费 → 双人复核发药 → 部分退药退款。
4. 住院押金 → 长期隔日医嘱 → 执行实例 → 分类摆药与统领 → 发药 → 病区基数药使用。
5. 全院调价 → 库存估值与交易价对比 → 发药收费对账 → 凭证与日月结 → 科室消耗分析。
6. 原料采购质检 → 配方生产 → 工序与成品质检 → 成本结算 → 成品入库与销售。
7. 展示负库存阻断、过期阻断、越权拒绝和重复操作不重复扣账，最后打印与导出。
